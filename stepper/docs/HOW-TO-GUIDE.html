HackerFab Stepper for Windows

The complete how-to guide for the HackerFab Stepper app: installing it, connecting the camera, stage and projector, running an exposure from start to finish, and fixing things when they go wrong.

The projector shows images in red light only. Photoresist does not react to red, so you can move the stage, focus, and line up the pattern as long as you like.

The pattern is projected with the blue/UV light that exposes the resist. The stage is locked while the pattern is on, and the timer decides the dose.

1Before you begin

HackerFab Stepper controls a maskless photolithography stepper. Instead of a physical mask, a DLP projector shines a pattern image through the optics onto a resist-coated chip sitting on a motorized stage. A USB microscope camera looks at the same spot so you can see what you are doing.

This guide covers the standalone HackerFab Stepper app for Windows, macOS and Linux. It runs without installing Python. It is built from the same source code as the run.bat launcher in the repository, including alignment-marker detection.

How a session goes

  1. Prepare the hardware. Projector on as an extended display, stage controller plugged in, camera in a USB 3.0 port.
  2. Start and connect. Pick the stage in the setup window; the camera connects by itself.
  3. Choose a pattern. Any PNG, JPEG, BMP or TIFF image.
  4. Focus and align in red. Move the stage to the spot you want and bring the image into focus.
  5. Expose in UV. Set the exposure time and start. The pattern is shown fullscreen for exactly that long.
  6. Record. Each exposure is logged in the chip record with its position, time and pattern file.

Words used in this guide

TermMeaning
StageThe motorized platform that holds the chip. X and Y move it sideways; Z moves it toward or away from the optics to focus.
ControllerThe board that drives the stage motors: a BTT SKR Pico running grblHAL (or an Arduino running GRBL). The app talks to it over a USB serial port such as COM5.
ProjectorThe DLP projector that forms the light pattern. Windows sees it as a second monitor.
PatternThe image you want to print. Bright pixels are where light lands.
Red modeWhat the app is in on the 2 · Focus (red light) tab. Only the red channel is projected.
UV modeWhat the app is in on the 3 · Expose (UV light) tab. Only the blue channel is projected, which is the light that exposes resist.
Focus scoreA number the app computes from the camera image. Higher means sharper. Shown as Focus · Red … UV … under the camera preview.
Chip, layer, exposureThe app's record keeping. A chip file holds layers; each layer holds the exposures made on it.
µmMicrometre, one thousandth of a millimetre. All stage distances in the app are in µm.
Config fileThe text file of settings, default.toml or config.toml, in the app's folder.

Safety

Do not look into the projector during an exposure

The exposure light is intense blue/UV. Do not look into the projector lens or the optical path, and do not look at bright reflections off the chip while a pattern is on.

Keep hands clear of the stage

The stage can move at any click. Some actions move all three axes at once: startup homing (when homing = true), Chip origin, Load / unload, Go to these coordinates, double-clicking an exposure in the chip record, and tiling. Chip origin, Load / unload and the double-click ask for confirmation first; the others do not.

Resist reacts to the UV focus mark too

Anything shown on the 3 · Expose (UV light) tab, including the UV focus crosshair, is projected in exposing light. Handle resist-coated chips under your fab's yellow lighting, and only project UV where you intend to expose.

Download

Open the project's GitHub page, click Releases on the right, and download the one file for your computer:

Install

  1. Windows: create a folder for the app, for example C:\HackerfabStepper\, and move the .exe into it. The app writes its settings, log and snapshots into its own folder, so give it a folder of its own rather than running it from Downloads. Optional: right-click it → Send to → Desktop (create shortcut).
  2. macOS: double-click the .zip to unpack it and drag HackerfabStepper.app into Applications. Settings, the log and snapshots go to Documents/HackerfabStepper.
  3. Linux: unpack it with tar xzf HackerfabStepper-Linux-x86_64.tar.gz into a folder of its own and run ./HackerfabStepper. For USB serial access your user may need to be in the dialout (Debian/Ubuntu) or uucp (Arch) group.

First launch

  1. Double-click the app. Nothing may appear for 10 to 30 seconds on the first run while it unpacks. Later starts are faster.
  2. If Windows shows "Windows protected your PC", click More info, then Run anyway. SmartScreen shows this for any program that is not code-signed. You only see it once per copy of the app.
  3. If macOS says the app "cannot be opened" or is from an unidentified developer, right-click the app → Open → Open. On newer macOS, go to System Settings → Privacy & Security, scroll down and click Open Anyway. macOS also asks once for permission to use the camera: click Allow.
  4. If the app vanishes or will not start, your antivirus may have quarantined it. Packaged Python programs are a common false positive. Restore it from quarantine and add an exception for the app's folder. On a managed lab PC, ask whoever administers it.
  5. The setup window opens. It is described next.

On the very first start the app creates these next to itself:

  • default.toml, the factory settings. Edit it in Notepad if you like.
  • src\uvFocusImage\plus.png, the crosshair used for UV focusing.
  • stepper_captures\, the default folder for camera snapshots.
  • HOW-TO-GUIDE.html, this guide, opened by Help & guide or F1. It is replaced automatically when you update to a newer version of the app, so do not edit it.
  • HackerfabStepper.log, where status messages and errors are written on each run. Once it passes 2 MB it is renamed to HackerfabStepper.log.old and a new one starts.
Where the files live

Windows and Linux: next to the app. If it cannot write there (for example in C:\Program Files), it uses %LOCALAPPDATA%\HackerfabStepper on Windows (paste that into File Explorer's address bar) or ~/.local/share/HackerfabStepper on Linux. macOS: always Documents/HackerfabStepper. To use a different folder on any system, set the environment variable HACKERFAB_HOME to it.

The setup window

1Settings file and Browse… choose which settings file to use. It is config.toml if that file exists (it appears after your first Save settings), otherwise default.toml. Use Browse… to pick another .toml file, for example one kept per station. Choosing a file rescans the stage ports using that file's settings.
2Stage controller lists every serial port Windows can see. Likely stage controllers come first, labelled [Arduino / GRBL]; an SKR Pico is recognized as an RP2040 device. No stage (run without hardware) is always last. The ↺ button rescans, for example after plugging the controller in. 3The status line explains the choice. Green ✓ Auto-selected means exactly one controller was found. Orange means several controllers or only an unrecognized device were found, so check the selection yourself. No serial ports found means nothing is plugged in or powered.

What happens when you click Start

  1. The settings file is read. If it has an error, a message names the problem and you stay in the setup window.
  2. The app opens the stage port at the configured baud rate (115200). If that fails, it continues in simulation mode and a Check your settings message explains why. The same message lists any values in the config file it could not understand, and the default it used instead.
  3. If homing = true, the stage homes: all axes drive to their limit switches. Make sure nothing is in the way. If homing fails or takes more than two minutes, a message says so and the app continues without it.
  4. The camera search starts in the background, and the app enters red mode.
  5. The main window appears.

A few more things worth knowing:

  • Hover over a control for a moment to see a short explanation of what it does.
  • The bar between the fullscreen hint and the tabs is the exposure progress bar.
  • The mouse wheel scrolls the whole page when the window is small. The window can shrink to 900 × 650; on narrow windows the projector preview moves below the camera.
  • Fullscreen views (camera or projector) fill the app's own window. Press Esc or the × button to return. Closing the projector fullscreen during an exposure stops the exposure.
  • Close the app with the window's normal close button. It releases the camera and the stage port on the way out.

4Connect the camera

The station uses an Arducam 20MP IMX283 USB 3.0 camera (model B0477) with a 16 mm C-mount lens. Any standard USB (UVC) camera works the same way. Basler and FLIR cameras need their vendor software and the Python version of the app; they are not supported by the app.

Plugging in the Arducam

  1. Use a USB 3.0 port directly on the computer: the blue one, or the one with the SS logo. On USB 2.0 the camera is limited to 1280 × 720 at 10 frames per second.
  2. Use the cable that came with the camera (USB-A to USB-C). Many USB-C cables only carry USB 2.0 speeds.
  3. No hubs, docks or extension cables. They are the most common cause of green or flickering video.
  4. Close every other camera program before connecting: PotPlayer, the Windows Camera app, Zoom, Teams, OBS, the Arducam viewer. Only one program can use the camera at a time.

How automatic connection works

With the default settings you do not need to do anything; the camera connects on its own within about 15 seconds of launch. Behind the scenes:

  • On Windows the app captures through Media Foundation, the same system the Windows Camera app uses. The older DirectShow system gives this camera a solid white image, so it is not used unless you ask for it.
  • It lists cameras by name and tries any camera with "Arducam" in its name first, so a laptop's built-in webcam is not picked by mistake.
  • For each camera it tries 1280 × 720 at 30 fps, then 640 × 480 at 30 fps, then 640 × 480 at 15 fps, then the camera's own default. A mode is accepted once four clean frames arrive in a row.
  • Frames that are mostly solid green are rejected. That pattern means image data was lost on the USB link.
  • Capture runs in a separate background process with a watchdog, so a stuck camera driver cannot freeze the app. If the camera sends nothing for 12 seconds, the status reads Camera timed out.

When it works, the text under the preview reads like Connected · 1280 × 720 · 30 fps · … · 1, giving the resolution, frame rate, pixel format and device, and the sidebar shows Camera · live.

The Settings → Camera tab

1The Settings tabs: Camera, Stage and Appearance. The Save settings button is at the bottom of the page, below the tabs.
2Camera and Find cameras. Leave it on Automatic selection, or click Find cameras and pick a camera by name. You can also type a camera number such as 1.
3Image quality. Automatic · recommended tries the modes listed above. Choose a capture mode opens Manual capture, where you set Width, Height and Frame rate. On Windows the List modes button finds nothing (it relies on a Linux tool), so type the values in. Image format is ignored with Media Foundation. In manual mode, the app refuses to connect if the camera returns a different resolution or frame rate than you asked for, rather than quietly using something else.
4Skip broken (all-green) frames. Leave on. Turn it off only if your sample genuinely fills the view with green, since it would otherwise be rejected.
5Camera driver. Standard USB camera for the Arducam. Camera off disables the preview entirely. Basler and FLIR do not work in the app.
6Connect camera applies the choices above right away. It is refused with Device busy during an exposure or autofocus. It does not save anything; use Save settings to keep your choice.
7The status text and Copy camera report (for asking for help), which copies the selected device, detected cameras, and recent attempts to the clipboard. Paste it into any message asking for help.

Coloured horizontal bands in the camera image

A DLP projector doesn't shine continuously: it flashes its colours in quick succession, a couple of hundred times a second. The Arducam's sensor reads the image out row by row (a rolling shutter), so with a short exposure each band of rows catches a different flash and you see evenly spaced stripes. They multiply at higher resolution because the readout takes longer. They also make the focus score jump, which upsets autofocus.

  1. Settings → Camera → Exposure: choose -5 · 31.2 ms or -4 · 62.5 ms and click Connect camera. The camera status line then ends with exposure -5 (31.25 ms). If it says NOT applied, the camera ignored it.
  2. Dim the red image with Red brightness on the 2 · Focus (red light) tab until the preview isn't washed out. A completely overexposed Arducam image turns solid pink.
  3. Use a moderate resolution (1280 × 720 or 1920 × 1080) for focusing.

Setting an exposure makes the app capture through DirectShow, because this camera ignores exposure changes through Media Foundation. Camera default leaves the camera's own setting alone (the Arducam defaults to its shortest exposure, −11).

Recommended settings for the Arducam

  • Everyday use: leave everything automatic. You get 1280 × 720 at 30 fps.
  • When you want full HD: choose Choose a capture mode, enter 1920, 1080, 30, click Connect camera, then Save settings. This needs a genuine USB 3.0 connection.
  • Stuck on USB 2.0: manual mode with 1280, 720, 10.
Resolution affects calibration

Anything measured in camera pixels, such as the alignment marker coordinates in the [alignment] section, is only valid at the resolution it was calibrated at. If you change resolution, recalibrate those values.

Image brightness

The app only changes a USB camera's exposure if you choose one under Exposure, and never changes its gain. The red-exposure and uv-exposure settings apply only to Basler and FLIR cameras. If the picture is too bright or too dark, adjust the aperture ring on the lens (the 16 mm lens goes from F1.4, brightest, to F16, darkest) or the projector brightness.

Snapshots

  1. On the Main screen page, type a filename under the camera preview. The default output_%T.png produces names such as output_2026-09-23_14-05-11.png.
  2. Click Save camera photo. The full-resolution camera frame, not the smaller preview, is saved into the snapshot folder: stepper_captures\ in the app's folder unless you chose another under Image alignment, Camera photos. The green Saved … line shows exactly where it went. Characters Windows does not allow in file names, such as : or ?, are replaced with -.

5Connect and move the stage

Connecting

  1. Power the stage and plug the controller into the PC before starting the app.
  2. In the setup window, choose the controller under Stage controller. If you are not sure which COM port it is, open Windows Device Manager, expand Ports (COM & LPT), and unplug and replug the controller to see which entry disappears and returns.
  3. Click Start and check that the sidebar says Stage · connected.

To make a port the default, set it in Settings, Stage, Serial port (for example COM5), click Save settings and restart. auto leaves the choice to the setup window's scan.

Simulation mode

Choosing No stage (run without hardware), or setting enabled = false under [stage], runs everything without moving anything. The position fields still update, so this is a safe way to learn the controls or test patterns.

Axis directions

  • X and Y pan the camera's view across the chip.
  • Z is focus. +Z should bring the camera and the chip's surface closer together.
  • By default the app reverses Z (invert-z = true) to suit this station's wiring. It reverses both movement and the displayed position, so the numbers stay consistent.
Check Z direction on a new setup

Select a 10 µm step, press + Z once, and watch the camera image. If the gap got bigger instead of smaller, go to Settings, Stage, toggle Reverse Z direction, Save settings and restart the app. Do this before relying on saved positions or autofocus.

Moving the stage

The stage controls are in the middle of the 2 · Focus (red light) tab, in a panel titled Move the stage.

ControlWhat it does
X · µm, Y · µm, Z · µmShow where the stage was last sent. Type new values and click Go to these coordinates to move there directly.
Distance per click · µmHow far each arrow click moves. Type any positive number, or pick a preset: 1, 10, 50 or 250.
↑ Y, ↓ Y, X ←, X →Move one step in that direction.
− Z, + ZMove focus one step.
Chip origin, Load / unloadMove all three axes to fixed positions set in the code, after asking you to confirm. They only work when the stage has homing sensors (homing = true).

The 3 · Expose (UV light) tab has the same panel without the X and Y arrow buttons, so you can refine focus in UV mode without accidentally shifting the pattern. All movement controls are greyed out while an exposure or autofocus is running.

When the stage refuses to move

If the controller rejects a move, a Stage did not move message explains why in plain language: for example that the controller is locked in ALARM mode after hitting a limit switch, that the move is outside the stage's travel, or that the USB connection was lost. The position fields keep the last position the stage actually reached, so they never show a move that didn't happen.

If the stage disconnects

If the controller drops off USB (a loose cable, or the board resetting when the motors draw power), the sidebar shows Stage · DISCONNECTED, the move buttons are disabled, and a Reconnect stage button appears under it. Fix the cable or power and click it. After reconnecting, the position fields are read back from the controller. If it keeps happening while the motors move, try a shorter USB cable, a different port, or a powered USB hub.

Long moves and travel limits

A single click that would move the stage more than 2 mm asks for confirmation first. You can also give the stage hard limits with x-limits, y-limits and z-limits under [stage] in the config file (in µm, for example y-limits = [-15000, 0]). Moves outside them are refused with a message. Measure your stage's real range before turning these on.

When the app starts, it reads the stage's current position from the controller instead of assuming 0, 0, 0.

Before every exposure the app also checks that the stage has stopped moving. Move commands return as soon as the controller accepts them, so right after Go to these coordinates the stage can still be travelling. The exposure waits up to 20 seconds for it to settle, and if it doesn't, the exposure is not started and a message says why.

Homing

If the stage has limit switches and GRBL homing is configured on the controller, set homing = true under [stage]. The stage then homes every time the app launches, which makes positions repeatable between sessions and enables the Chip origin and Load / unload shortcuts. Controller settings such as steps per mm, speeds and travel limits are set on the controller itself, not in this app; see the GRBL section of the repository README.

6Set up the projector

Patterns are drawn on a fixed 1280 × 720 canvas and shown in a dedicated projector window: a borderless window that exactly covers the projector's display, while all the controls stay on your laptop screen. The mouse pointer is hidden over it, so it can't be projected onto the resist.

  1. Connect the projector and set Windows to Extend. Press Win + P and choose Extend. In Duplicate the projector just mirrors the laptop screen, so it projects the app's controls, and if the camera looks through the projector optics it films its own output (a feedback loop).
  2. Keep the projector display settings fixed. In Settings, System, Display, select the projector, set Scale to 100% and leave the resolution at its recommended value. Changing either later changes how big the pattern is on the chip.
  3. Start the app. The projector window opens by itself on the first display that isn't your main screen. The sidebar shows Projector · Display 2 · ….
  4. Check or change the display under Projector window in the What the projector shows panel. Pick the projector from the list and click Open projector window. Save settings on the Settings page remembers the choice. If the projector isn't detected, choose Movable window, drag it onto the projector and double-click it for fullscreen.

With no projector window open (for example on a single-screen PC), exposures fill the app's own window instead, so the app must then be on the projector display. Clicking the What the projector shows preview always shows a full-size view on the laptop screen; closing it doesn't affect the projector window.

Esc stops a running exposure

Pressing Esc in the app, Stop exposure or Clear projector (black) aborts the exposure and clears the pattern. The exposure is still logged, marked as aborted. The projector window can't be closed mid-exposure.

To never open the projector window, set window = "off" under [projector] in the config file.

7Your first exposure

This is the complete procedure for one exposure. Parts 4 to 6 explain the hardware setup it assumes.

Prepare

  1. Turn on the projector (extended display), power the stage, and plug in the camera and controller.
  2. Open the app, check the stage port, click Start.
  3. Confirm the sidebar shows Camera · live and Stage · connected. If not, see Troubleshooting.
  4. Load the chip. With homing, click Load / unload on the 2 · Focus (red light) tab to bring the stage to its loading position; otherwise move it by hand with the arrows. Place the chip under yellow light.

Choose the pattern

  1. Open the Pattern tab on the Main screen page.
  2. Click Choose image… and pick a PNG, JPEG, BMP or TIFF file.
  3. Check the result: the file name, its size in pixels, and a preview appear.
How the pattern is used

The image is fitted onto the 1280 × 720 projector canvas, keeping its proportions. For the exposure only its blue channel is projected, so draw patterns in white or blue on black. Bright pixels are where the resist receives light. Transparent areas count as black (no light), and 16-bit images are scaled down to 8 bits rather than clipped.

Focus and align in red Red mode

  1. Open the Focus & align tab. The app switches to red mode.
  2. Pick what to project in red, using the options on the left:
    • Solid red (whole area): an even red field. Good for finding the chip and general focusing.
    • The pattern, in red: your pattern drawn in red, showing exactly where it will land.
    • The pattern inverted, in red: the pattern with light and dark swapped.
    • What to project in red: your own focusing image; click the thumbnail underneath to choose a file.
    Red brightness, underneath, dims whichever red image is shown; lower it if the camera preview washes out with a long exposure. The small image on the right of the tab shows the current pattern for reference. Solid red (whole area) is selected when the app starts.
  3. Put the red image on the projector. With the app window on the projector display, click the What the projector shows preview for fullscreen (Part 6).
  4. Find the spot to expose. Pick a large step such as 250 µm and use the X and Y arrows, then smaller steps as you get close.
  5. Focus. Use − Z and + Z with 10 µm steps, then 1 µm, watching the camera image and the Focus · Red score under it. Aim for the highest score.
  6. Or let autofocus do it: Image alignment page, Autofocus now. It measures the focus score at the current Z and 20 µm either side to find which way is sharper, moves in 10 µm steps until the score drops, scans ±8 µm around the best point in 2 µm steps, and finishes at the sharpest Z it measured. It needs a live camera. If it cannot run, or cannot tell which way is sharper, a message explains what to do.
  7. Fine-tune placement without moving the stage if needed, using Image alignment, Shift / rotate the projected image to shift or rotate the projected image by pixels (Part 8).

Expose in UV UV mode

1UV focus. A crosshair (Plus Mark) or your own marks, projected in UV with Use selected mark to check focus in exposing light.
2Move the stage, as on the 2 · Focus (red light) tab but without the X and Y arrows, so you cannot shift the pattern by accident.
3Exposure time (milliseconds) and Posterize Cutoff.
4Start exposure, with the exposure progress bar below it.
5Before you expose, a live checklist: whether a pattern is loaded, the exposure time in seconds, whether the stage is connected, and a reminder about the projector display. Red lines are problems to fix first.
  1. Open the Expose tab. The app switches to UV mode and the projector goes dark; nothing is projected until you ask. If Save a photo automatically when entering UV is on, a camera snapshot named uv_mode_entry_<date-time>.png is saved at this moment.
  2. Optional, UV focus check. UV light often focuses at a slightly different Z than red; the tiling code in this app assumes 40 µm. On the left, Plus Mark is a crosshair: select it and click Use selected mark to project it in UV, then adjust Z with the Z buttons. Add mark image… adds your own mark images. The crosshair exposes resist where it lands, so do this on a spot you don't need, and click Clear projector (black) when done.
  3. Set Exposure Time (ms). The default is 8000, which is 8 seconds. The right value depends on your resist, projector brightness and optics; use your team's calibrated value. The pattern actually stays on about 30 to 40 ms longer than the number you enter, which is negligible at several seconds but significant for exposures under half a second.
  4. Optional, Posterize Cutoff (%). Tick it to turn the pattern into pure black and white: pixels brighter than the cutoff become fully on, the rest fully off. Useful for greyscale or anti-aliased images.
  5. Read the Before you expose list, and fix anything shown in red. Then check the window is on the projector display. The exposure is shown wherever the app window is.
  6. Click Start exposure. The app first checks that the stage has stopped moving (Part 5), then opens the projector fullscreen, projects the pattern, and fills the Exposure Progress bar. All movement and tab switching are locked. Do not press Esc or click × unless you want to abort.
  7. When the time is up, the projector goes black automatically. If the black fullscreen view is still showing, press Esc to return to the controls; that is safe once the exposure is over.

If you do need to stop early, Esc, the × button, Stop exposure and Clear projector (black) all end it immediately. An error message appears instead of an exposure if no pattern is chosen, or if the exposure time is not a positive number.

Afterwards

  1. Check the record. Chip records & tiling lists the exposure under Current Layer with its time, pattern file, stage position, duration, and whether it was aborted. The map marks where it was made.
  2. Save the chip record. Click Save record as… (or New record before you start) to give the chip a file. After that it saves itself on every change. If you forget, the app asks before you start a new record or close the window.
  3. Next site: go back to 2 · Focus (red light), move, focus, and expose again.
  4. Unload: Load / unload (with homing) or move the stage by hand, then close the app.

8The Alignment page

Image Adjustment

Moves or rotates the projected images on the canvas, instead of moving the stage. It affects the pattern, the red focus image and the UV focus image alike.

  • Absolute: enter X (pixels), Y (pixels) and θ (degrees), then click Apply position. All three start at 0.
  • Relative: under Adjustment, the +X, −X, +Y, −Y, +T and −T buttons nudge by the amounts in Step Size (pixels, pixels, degrees), which default to 10, 10 and 10.

Save photos to, Choose folder…Where snapshots go. Defaults to stepper_captures\ in the app's folder.
About the detector

Marks are found by a small YOLO neural network trained on photos of real alignment marks (ckpts/best.onnx). It runs on OpenCV, built into the app, so no extra software is needed. The calibrated mark positions under [alignment] were measured on one station's camera; if Auto-align moves the wrong way or too far on yours, recalibrate them as described in docs/guide.md.

9The Wafer & tiling page

Map

A 10 mm × 10 mm plan of the stage area. It shows where the stage is now and draws a rectangle for every exposure on the chip, sized to the pattern's footprint of about 1037 × 583 µm.

Chip record

The chip record keeps a history of what was exposed where, layer by layer, in a JSON file you choose.

Tiling

Tiling exposes a pattern larger than one field by cutting it into overlapping tiles and exposing them one after another in a snake pattern.

  • Split pattern into tiles cuts the current pattern into tiles saved in a tiles\ folder in the app's folder, and fills in the tile counts.
  • Tiles sit on an even grid. Where the last row or column reaches past the pattern, the extra area is black (no light).
  • The X and Y boxes set Distance between tiles (µm), the stage move between tiles (defaults 983 and 512 µm), and Number of tiles, filled in by the split. A negative number reverses that direction.
  • Start tiling asks for confirmation, then for each tile: moves, autofocuses in red, finds the previous tile's marks on the edge where that tile is (left, right or top) and corrects the stage position, shifts Z by the UV offset, autofocuses in UV, exposes, and returns to red.
  • Stop tiling (or Stop exposure) stops the whole run. It also stops by itself if an exposure is refused or the stage fails. At the end a summary lists what happened to each tile, including any tile where no marks were found.
  • Photograph the whole chip moves the stage over the chip in a grid, photographs each spot, and stitches an overview image shown under the button.
Before a real tiling run

Try it on a scrap chip first: check with Detect alignment markers in real time that the marks are found, and that the stage steps between tiles go the right way on your stage.

12Troubleshooting

Two things answer most questions: the log file HackerfabStepper.log in the app's folder (the newest run is at the bottom) and, for camera problems, Settings, Camera, Copy camera report (for asking for help).

Starting the app

"Windows protected your PC" appears

The app is not code-signed, so SmartScreen does not recognize it. Click More info, then Run anyway.

The app disappears, or antivirus blocks it

Packaged Python programs are often flagged by mistake. Restore the file from your antivirus quarantine and add an exclusion for the app's folder. On university-managed PCs you may need IT to approve it.

Nothing happens for a while after double-clicking

The app unpacks about 70 MB before showing anything, which takes 10 to 30 seconds on the first run and on slow disks. Wait before clicking again; several copies starting at once will compete for the camera.

A "Check your settings" message appears at startup

It lists values in the config file the app could not use, and what it used instead, plus stage or camera connections that failed. The app is still usable. Fix the listed lines in the config file (or in Settings) and restart.

An error box appears, or the app closes straight away
  1. Open HackerfabStepper.log and read the last lines; the error is described there.
  2. If it mentions the config file, rename config.toml to config.old.toml and start again with the defaults.
  3. If the log is not in the app's folder, the folder is read-only and the app is using %LOCALAPPDATA%\HackerfabStepper; look for the log there.

Camera

Camera stays "offline / connecting" or says "No usable camera mode"
  1. Close every other program that might hold the camera, including PotPlayer, Camera, Zoom, Teams, OBS and the Arducam viewer.
  2. Unplug the camera, wait five seconds, and plug it into a blue USB 3.0 port directly.
  3. Click Reconnect camera under the camera status. Or go to Settings, Camera, click Find cameras, then Connect camera.
  4. If it still fails, check Windows camera privacy: Settings, Privacy & security, Camera, and make sure Let desktop apps access your camera is on.
  5. Still failing: copy the camera diagnostics and send them with the log.
The laptop's built-in webcam is shown instead of the Arducam

Settings, Camera: click Find cameras, choose the Arducam by name, click Connect camera, then Save settings. Alternatively set device to the Arducam's number in the config file.

The image is solid white

The capture system is set to DirectShow. Set backend = "auto" in config.toml and restart. If it is already "auto", close the aperture ring on the lens a few stops in case it is simply overexposed.

Green bands, a green block, or flickering

Image data is being lost on the USB link. Use a blue USB 3.0 port directly, the original cable, and no hub or dock. Try flipping the USB-C plug at the camera. If you cannot get a USB 3.0 connection, use manual mode at 1280 × 720, 10 fps.

Where did my snapshot go?

Into the snapshot folder, stepper_captures\ in the app's folder unless you changed it on the Image alignment page. The green Saved … line under the file name shows the exact path of the last one.

Snapshot button is greyed out

Snapshots need a live camera frame. Wait for Camera · live, or fix the camera connection first.

"Driver did not accept requested mode"

In manual mode the camera answered with a different resolution or frame rate than requested. Pick a mode the camera supports, such as 1280 × 720 or 1920 × 1080 at 30 fps on USB 3.0, or 1280 × 720 at 10 fps on USB 2.0.

Stage

"Stage did not move"

The message says why. ALARM mode means the controller locked itself, usually after a limit switch was hit: enable homing and restart, or unlock it with $X from a G-code terminal, then restart the app. Travel limits means the target is outside the stage's range. Lost contact means the USB link dropped: check the cable and power, then restart.

"Exposure not started: the stage has not stopped moving"

The controller did not report that it was idle within 20 seconds. Wait a moment and try again. If it keeps happening, the message shows the state the controller reports; Alarm is handled as above, and Hold means a feed hold is active on the controller.

No ports appear in the setup window
  1. Check the controller is powered and its USB cable is a data cable, not charge-only.
  2. Click ↺ to rescan.
  3. Check Device Manager, Ports (COM & LPT). If the device shows a warning icon, it needs a driver (CH340-based boards often do).
Stage shows "simulation" even though I picked a port

Opening the port failed, and the reason is in the log (Stage connection failed (COM5): …). Most often another program has the port open, such as the Arduino IDE serial monitor or a G-code sender. Close it and restart the app.

The stage moves the wrong way in Z

Settings, Stage, toggle Reverse Z direction, Save settings, restart. For X or Y, the direction is set by the motor wiring or the controller's direction settings.

Chip origin and Load / unload are greyed out

They need homing. Set homing = true under [stage], but only if the stage has limit switches and homing is configured on the controller.

Autofocus shows a message instead of focusing

It needs a live camera image, so connect the camera first. If it says it cannot tell which way is sharper, the image has too little detail or is far out of focus: focus roughly by hand and project Solid red (whole area) or a pattern with sharp edges. It does nothing while an exposure is running.

Autofocus ends up out of focus

Autofocus assumes it starts reasonably close to focus. Get roughly in focus by hand first, and project Solid red (whole area) or a pattern with sharp edges, which give the focus score something to measure.

Projector and exposure

Nothing is projected in red on the Focus & align tab

The projector shows only what the app's fullscreen view shows. Move the window to the projector display and click the What the projector shows preview. If you picked What to project in red without loading an image, it is blank: choose Solid red (whole area) or click the thumbnail to load one.

The projector mirrors my laptop screen

Windows is in Duplicate mode. Press Win + P, choose Extend, then pick the projector under Projector window and click Open projector window.

The pattern does not appear on the projector
  1. Check Windows is set to Extend with Win + P.
  2. Check the sidebar says Projector · Display …. If it says in this window, open the projector window from the What the projector shows panel.
  3. If the wrong display is covered, choose the projector in the list; the window moves there.
Coloured stripes across the camera image

The projector's colour flashes against the camera's rolling shutter. Set Settings → Camera → Exposure to −5 or −4, then lower Red brightness until the image isn't washed out. See Part 4.

The camera image is solid pink or white

It's completely overexposed. Lower Red brightness, or choose a shorter exposure.

The exposure stopped early

Pressing Esc, clicking ×, Stop exposure or Clear projector (black) during an exposure stops it. The record marks it as aborted.

"Choose a pattern" or "Exposure time" message when starting

Pick a pattern on the 1 · Choose pattern tab first, and enter a whole number of milliseconds greater than zero.

The pattern is the wrong size or in the wrong place on the chip

Check that the projector display's resolution and scale have not changed (Part 6), that Border Size is 0, and that Shift / rotate the projected image is back at 0, 0, 0.

Settings and files

Grey thumbnails in the chip record

The pattern file for that exposure is not at the path saved in the record, because it was moved, deleted, or the record came from another PC. The exposure data is still there; only the preview is missing.

My settings were not kept

Click Save settings at the bottom of the Settings page, and make sure the setup window then shows config.toml. Stage changes also need a restart.

The comments in my config file vanished

Saving from the app rewrites the file without comments. The previous version is kept as a .bak file beside it.

Text is too small or too big

Settings, Appearance, Text size, Preview look, then Save settings. For more, see HACKERFAB_UI_SCALE in Part 10.

Reporting a problem

Include what you did and what happened, the last 50 lines of HackerfabStepper.log, the camera diagnostics if it is a camera problem, and your Windows version. Open an issue on the repository or post in the team channel.

13For maintainers

What the standalone app is

A PyInstaller build of the stepper/ folder: a one-file program on Windows and Linux, and an .app bundle on macOS. It bundles Python 3.12, OpenCV (headless), NumPy, Pillow, pyserial, toml and ttkbootstrap. Alignment-marker detection uses ckpts/best.onnx on OpenCV's DNN module (src/alignment_detector.py), so neither the app nor run.bat / run.sh needs PyTorch.

What happens at startup

  1. multiprocessing.freeze_support() runs first. The camera worker is a separate process that re-launches the app, and this line makes those copies act as workers instead of opening another window.
  2. The app picks its home folder (see Where the files live) and turns off Media Foundation's hardware transforms on Windows (OPENCV_VIDEOIO_MSMF_ENABLE_HW_TRANSFORMS=0), which can otherwise make opening a camera slower than the capture watchdog allows.
  3. Output is sent to HackerfabStepper.log in that folder, rotated at 2 MB.
  4. default.toml and src/uvFocusImage/plus.png are copied out of the bundle if they are missing; this guide is refreshed if the bundled copy differs.
  5. gui.main() runs. An unhandled error is logged and shown in a message box; errors inside buttons are shown without closing the app.

The entry point is src/stepper_app.py. The build is defined in packaging/HackerfabStepper.spec and driven by packaging/build.py.

Build on GitHub

The Build app workflow (.github/workflows/build.yml) runs the tests, then builds and smoke-tests the app on Windows, macOS (Apple silicon and Intel) and Linux on every push and pull request. The files are attached to the workflow run under Artifacts. A push to main also refreshes the Latest build pre-release on the Releases page, and pushing a version tag publishes a normal release:

git tag v1.0.0
git push origin v1.0.0

Build on your own computer

cd stepper
python -m venv .venv-build
.venv-build/bin/python -m pip install -r packaging/requirements-build.txt     (Windows: .venv-build\Scripts\python)
.venv-build/bin/python packaging/build.py

Use Python 3.10 to 3.13 (3.12 preferred). On Linux run the last line under xvfb-run -a if there is no desktop. The result is in dist/release/.

Smoke test

HackerfabStepper --smoke-test builds the whole interface with no hardware, checks that the app can start child processes, and (except on macOS, where opening a camera triggers a permission prompt) starts a camera worker against a camera number that does not exist and checks that it reports back. It exits with code 0 and writes SMOKE TEST PASSED to the log on success.

Changing defaults

default.toml is bundled inside the app and only copied out when missing. After changing it in the repository, rebuild, and tell people to delete their old default.toml to pick up the new one. Their config.toml is never touched.

Running the tests

cd stepper
./run_tests.sh          (Linux/macOS; uses an invisible screen when Xvfb is installed)
set PYTHONPATH=src && python -m unittest discover -s tests     (Windows)

tests/test_regressions.py and tests/test_usability.py cover the bugs fixed while auditing the app and the usability features: exposures locking up when a pattern file is missing, dropdown focus breaking fullscreen, the stage and autofocus fixes, snapshots, pattern transparency, config typos, confirmations, save prompts, the checklist, Help and Reconnect. tests/test_stage_connection.py covers USB dropouts, reconnecting, travel limits and the black projector background. The GUI tests need a display, and answer every dialog automatically so they can never hang.
