1Before you begin

HackerFab Stepper controls a maskless photolithography stepper. Instead of a physical mask, a DLP projector (TI DLPDLCR471TPEVM) shines a pattern image through the optics onto a resist-coated chip on a motorized stage. A USB microscope camera (Arducam B0477, 20 MP) looks at the same spot so you can see what you are doing.

This guide covers the Windows exe, HackerfabStepper.exe. It runs without installing Python. It is built from the same source code as the run.bat launcher in the repository, minus the YOLO alignment-marker model, which would make it over 1 GB.

How a session goes

  1. Prepare the hardware. Projector on and set as an extended display (Win + P, Extend), stage controller plugged in, camera in a USB 3 port. Optionally, the projector board's own USB cable for LED control.
  2. Launch. Pick the stage in the setup window. The camera, the projector output and the LED control connect by themselves.
  3. 1 Pattern. Choose the image to expose.
  4. 2 Focus. In red light, move to the spot, line up and focus.
  5. 3 Expose. Set the time, check the list, press Start exposure.
  6. Record. Every exposure goes into the chip record with its position, time and pattern file.

Words used in this guide

Safety

Do not look into the projector during an exposure

The exposure light is intense blue. Do not look into the projector lens or the optical path, and do not look at bright reflections off the chip while a pattern is on.

Keep hands clear of the stage

The stage moves whenever you press an arrow, a key, Go to…, Home or Autofocus, and during tiling. Moves of several axes at once over long distances ask for confirmation first.

Only blue light exposes, and the blue focus mark is blue light too

The badge on the Projector panel always tells you which light is on: RED · SAFE is safe for resist, EXPOSING and BLUE MARK expose it. The Projector dot in the top bar turns purple and reads BLUE ON whenever blue light is on, on every page. Handle resist-coated chips under your fab's yellow lighting.

Install

  1. Create a folder for the app, for example C:\HackerfabStepper\. The app keeps its settings, log and snapshots in the folder it lives in.
  2. Put HackerfabStepper.exe in that folder. It is about 50 MB. If you downloaded it in parts, put all HackerfabStepper.exe.part* files and join-HackerfabStepper.bat in that folder and double-click the .bat: it joins the parts into HackerfabStepper.exe and checks the result, after which you can delete the parts. Replacing the exe keeps your config.toml.
  3. Copy in this guide and the README, HOW-TO-GUIDE.html and README.md.
  4. Optional: a desktop shortcut. Right-click the exe, Show more options (Windows 11), Send to, Desktop (create shortcut).

First launch

  1. Double-click the exe. Nothing may appear for 10 to 30 seconds the first time while it unpacks.
  2. If Windows shows "Windows protected your PC", click More info, then Run anyway. The exe is not code-signed.
  3. If the exe vanishes, your antivirus may have quarantined it (a common false positive for packaged Python programs). Restore it and add an exception for the folder.
  4. The setup window opens. See below.

On the first start the app creates, next to itself: default.toml (factory settings), src\uvFocusImage\plus.png (the UV focus mark), stepper_captures\ (snapshots), HOW-TO-GUIDE.html (this guide; replaced when you update the exe) and HackerfabStepper.log (status messages and errors, rotated at 2 MB). Your own settings are saved to config.toml.

If the exe's folder is read-only

For example under C:\Program Files: the app then keeps these files in %LOCALAPPDATA%\HackerfabStepper. Paste that into File Explorer's address bar to open it.

The setup window

  1. Config file. Leave it on config.toml (or default.toml the very first time).
  2. Stage port. The stage controller is detected and marked [Arduino / GRBL]. Choose No stage to run without one (simulation: nothing moves). ↺ scans again after plugging something in.
  3. Launch. The main window opens, maximized.

4The camera

Connecting

Plug the Arducam into a blue USB 3 port directly (no hub or dock). The app finds it by name and opens it at its highest resolution at the lowest frame rate: 5472 × 3648 at 9 fps for the B0477. The picture on screen is a reduced preview; snapshots and focus measurements use the full resolution.

The camera toolbar shows CONNECTING, then LIVE. If it shows NO CAMERA, the message on the picture says why, and Reconnect tries again (close Zoom, Teams, OBS, the Camera app and the Arducam viewer first).

Resolution

The list under the picture shows every resolution the camera reports, plus Highest resolution (recommended). Choosing one reconnects the camera in a few seconds. For the cameras this app knows, the modes are:

A low frame rate is not a problem here: it leaves room for the longer exposures that remove projector stripes.

Why the picture had stripes, and how they are removed

A DLP projector shows red, green and blue one after another many times a second. The camera reads its sensor row by row (a rolling shutter), so rows exposed at different moments catch different amounts of light: horizontal bands. Three things make them disappear:

  1. Stripe-free exposure. If each row is exposed for a whole number of the projector's colour cycles, every row gets the same light. While red light is on, the app tries exposures of 16, 31, 62.5 and 125 ms, measures how striped each one is, and keeps the best. This takes about 10 seconds the first time and is remembered.
  2. Fixed white balance. The camera's automatic white balance sees a red-only picture and turns up green and blue, which magnifies the faint green/blue light the projector leaks into bold teal and pink bands. The app keeps white balance fixed at 4500 K.
  3. Unused LEDs off. With the projector's USB cable connected, the app turns the green and blue LEDs off while focusing, so they cannot leak at all (Part 6).

A software Stripe filter evens out anything left over in the live picture (never in snapshots).

Automatic brightness

With Auto on next to Red brightness, the app keeps the brightest parts of the picture bright but not clipped. It does this mostly by dimming or brightening the red light, which keeps the stripe-free exposure and adds no noise; only if that is not enough does it raise camera gain, and as a last resort the exposure. The 2 Focus step shows what it is doing, for example Auto: settled · exposure -4 (62.5 ms) · red 45% · gain 100.

Automatic settings only run while red light is on. Moving the red brightness slider yourself turns Auto brightness off; moving exposure or gain yourself turns auto exposure off.

Keyboard

Arrow keys move X/Y, Page Up / Page Down focus, and holding Shift makes any of them 10× the step. Holding a key repeats like the buttons. Keys work when you are not typing in a field; click the camera picture to give them back to the stage.

If ▲ moves the picture the "wrong" way for you, reverse that axis in Settings → Stage → Arrow buttons and keys. It applies immediately.

When the stage refuses to move

A message explains why. ALARM: the controller locked itself (after a limit switch, or at power-up with homing enabled): enable homing and restart, or unlock it with $X from a G-code terminal. Travel limits: the target is outside the stage's range. Lost contact: check the USB cable and power, then restart. All stage controls are locked (greyed) while an exposure, autofocus, homing or tiling runs.

The position readout is read from the controller when the app connects and after homing, so it matches where the stage really is even if the controller kept its position from an earlier session. The arrows and keys make relative moves; Go to…, saved positions and double-clicking an exposure on the Chip page move to absolute positions in the controller's machine coordinates.

6The projector

The output window

  1. Press Win + P and choose Extend. The projector then is its own display. (In Duplicate mode it only mirrors the laptop screen.)
  2. Start the app. The output window opens on the first display that is not your main screen. The Projector dot turns green and the panel shows OUTPUT with the display's name.
  3. To change it, pick another display under OUTPUT; Open / Close opens or closes the window. Your choice is remembered.

Images are prepared at exactly the projector display's resolution, so every pattern pixel is one projector pixel. If Windows shows only one display when you start an exposure, the app asks whether to fill this screen with the pattern for the exposure (useful only in Duplicate mode) and gives the screen back afterwards.

What is being projected

BadgeMeaning
OFFBlack. Nothing is projected (and, with LED control, the LEDs are off).
RED · SAFERed light: solid red, your pattern in red, the inverted pattern, or your own focusing image, at the brightness shown. Safe for resist.
EXPOSINGThe pattern in blue light, with the seconds left. Exposes resist.
BLUE MARKThe blue focus mark (a plus sign). Exposes resist where it lands.
STARTINGYou pressed Start and the app is waiting for the stage to stop. Nothing is exposed yet; Esc cancels.

The thumbnail is the exact image on the output window. Click it, or Enlarge, for a larger preview window you can resize. The preview only mirrors the output; closing it never changes what is projected.

LED control over USB (recommended)

The projector board has its own USB port next to the HDMI input. With it connected to the computer, the app switches the LEDs:

Projector showsLEDs onWhy
Red lightRed onlyNo green or blue leaks onto the chip: no coloured bands in the camera, no stray blue on the resist.
Pattern / blue markRed + blueBlue exposes; red stays on so the exposure can never be dark (the pattern contains no red).
OffNoneTruly dark.
App closedNoneThe Windows desktop is not projected onto the chip after you close the app.
  1. Connect the projector board's USB port to the computer with the cable that came with it. Keep the HDMI cable connected too.
  2. Close TI's DLP EVM GUI if it is open: only one program can use the board at a time.
  3. Start the app. The LEDs dot turns green and the panel shows LEDs: red only · USB.
  4. Check it once: Settings → Projector → Test LEDs. The projector shows red, goes dark for 2.5 seconds, and comes back. Answer the question at the end.

Before an exposure the app switches the blue LED on and refuses to start if the projector does not accept the command, so an exposure can never silently be dark. If the board's USB cable is unplugged while the app runs, exposures are refused with a message until you plug it back in and click Settings → Projector → Reconnect LEDs (or turn LED control off); everything else keeps working.

The LEDs dot stays grey: "no TI projector found on USB"

The board's USB cable is not connected (the HDMI cable alone carries no commands), or it is connected to a charge-only cable. Connect it and click Settings → Projector → Reconnect LEDs.

"Windows has no usable driver for the projector's USB control interface"

The board normally installs as a standard WinUSB device by itself. If not, install the driver once with Zadig:

  1. Download Zadig from zadig.akeo.ie and run it.
  2. Options → List All Devices.
  3. Choose the projector's entry (a Texas Instruments / DLPC device; if there are several, the one marked Interface 0). Do not pick the camera, keyboard or mouse.
  4. Make sure the target driver is WinUSB and click Install Driver (or Replace Driver).
  5. In the app: Settings → Projector → Reconnect LEDs.
"The projector's USB interface is busy or has the wrong driver"

Close TI's DLP EVM GUI and any other program that talks to the board, then Reconnect LEDs. If it persists, see the Zadig steps above.

Test LEDs: the projector did not go dark

The board accepted the commands but nothing changed, so its firmware does not switch LEDs this way. Turn LED control off (Settings → Projector); the camera's stripe-free exposure and fixed white balance still work without it.

7An exposure, step by step

Prepare

Before you start

  • Top bar: Camera, Stage and Projector dots green (and LEDs, if the USB cable is used)
  • Chip record opened or created (Chip & map page) so exposures are saved to a file
  • Resist-coated chip loaded under yellow light

1 Pattern

  1. Choose pattern… PNG, JPEG, BMP or TIFF. Bright pixels get light; transparent pixels count as black.
  2. Check the details: the size, and whether it fills the projector exactly or is scaled to fit. For pixel-exact results, make the pattern the projector's resolution.
  3. Check the preview. It shows the pattern exactly as it will be projected: blue on black.
  4. Options: Border leaves a dark margin (percent of the field); Pure black & white turns grey pixels fully on or off at the cut-off. Shifting or rotating is on the Alignment page.
  5. Show it in red projects the pattern in red (safe) and switches to step 2, so you can see where it lands on the chip.

2 Focus red light

  1. Choose what the red light shows under RED LIGHT SHOWS: Solid (even red, best for finding the chip and focusing), Pattern (your pattern in red, to line it up), Inverted, or Image… (your own focusing picture).
  2. Find the spot with the arrow pad or arrow keys, a large step first, then smaller.
  3. Focus with Z + / Z − (or Page Up / Page Down) until the focus bar is as long as it gets, or press Autofocus (about 20 s; Stop or Esc cancels). Autofocus needs a picture with some detail and a start reasonably close to focus. It never moves more than 150 µm from where it started; if it finds no sharpest point, loses the camera, or is stopped, it moves back to the starting Z.
  4. Let the camera settle. The first time, the line under Auto exposure says Finding the stripe-free exposure… for about 10 seconds, then Auto: settled.

3 Expose blue light

  1. Exposure time in seconds (type it, or click 2, 5, 8, 10, 15 or 30 s). The equivalent in milliseconds is shown beside it.
  2. Optional blue focus check. Show blue focus mark projects a plus sign in blue to check focus in exposing light; it exposes resist where it lands, so use a sacrificial area. It switches back to red light when you leave the Expose step or the Operate page. Z offset during exposure moves Z by that many µm just before the exposure and back afterwards (blue light focuses slightly differently from red); 0 = no move.
  3. Read the checklist under BEFORE YOU EXPOSE: pattern, time, projector output, stage, LEDs. A red ✗ must be fixed first. The line just above the Start button sums it up (Ready: …, a note, or the first problem), so you can see it without scrolling.
  4. Press ▶ Start exposure. The app waits for the stage to stop (badge STARTING; nothing is exposed yet), saves a camera snapshot of the last picture before the light changes, draws the pattern, switches the blue LED on and times the exposure. The badge shows EXPOSING and the seconds left; the stage, the projector output, the camera resolution and the other controls are locked until it ends. The light goes off on time even if a message box happens to be open.
  5. To stop early, press ■ Stop exposure (Esc), Esc (also in camera fullscreen), or the red STOP. The record marks it as stopped with the time the light was really on, and the projector stays off.
  6. When it ends, the projector goes black and returns to the red light you were using. The status line and Last exposure confirm it.

Afterwards

  • Each exposure is in the chip record (Chip & map) with its time, position, duration and pattern. When a layer is complete, click Finish Layer.
  • Snapshots are in the snapshot folder (Settings → Files → Open).
  • Close the app with the window's ✕. It offers to save an unsaved chip record, remembers your settings, and switches the projector LEDs off.

8The Alignment page

Image position on the projector shifts or rotates everything the projector shows (pattern, red light and blue mark together), in projector pixels and degrees. Type values and click Apply, or use NUDGE: pick a step (1, 5, 20, 100 px; 0.05, 0.2, 1°) and click the arrows, or ⟲ (counter-clockwise) and ⟳ (clockwise). Reset returns to 0, 0, 0. Use it with Show it in red to line up a new layer with features already on the chip.

Alignment markers: automatic marker detection needs the ultralytics/PyTorch packages and a trained model, which are not in the exe. Use run.bat when you need it.

Automatic focus: the option to autofocus automatically when tiling switches between red light and exposure.

9The Chip & map page

Exposure map: a 1 × 1 cm map with the current field (red outline) and every exposure made (filled).

Chip record: Open, New and Save As a chip file (JSON). Exposures of the current layer are listed with a thumbnail and position; double-click one to move the stage back there (it asks first). Finish Layer starts a new layer; Delete Exposure removes the selected one. With a chip file chosen, every change is saved immediately.

Tiling (advanced) exposes a pattern larger than one field in several tiles: Segment Images cuts the pattern into projector-sized tiles with overlapping alignment marks (saved in stepper_tiles inside the snapshot folder), Begin Tiling asks once, then moves, focuses and exposes tile by tile. Capture & Stitch photographs the area and overlays the pattern, then returns the stage to where it started. Manual stage controls are locked during both; STOP or Esc ends the run after the current step. Automatic marker alignment between tiles needs the alignment model, which the exe does not include.

12Troubleshooting

Two things answer most questions: the log HackerfabStepper.log next to the exe (newest run at the bottom) and, for camera problems, Settings → Camera → Copy camera diagnostics.

Camera

The camera picture is black
  1. Check that the projector shows red light (badge RED · SAFE) and that the light reaches the chip.
  2. Click Adjust… under the picture, then Reset. Then pick a lower resolution from the list under the picture (for example 1920 × 1080) to see whether the picture comes back.
  3. After about 4 seconds of black frames the app writes a line starting with Camera picture is black to HackerfabStepper.log, with the camera's settings. Send that line with your report.
Coloured stripes are still visible
  1. Make sure red light is on and Auto exposure is on in step 2, then click Find stripe-free exposure and wait for Auto: settled.
  2. If the Focus step says The camera did not accept exposure…, close other camera programs and click Reconnect. If it keeps saying so, send the camera diagnostics (Settings → Camera → Copy camera diagnostics).
  3. Connect the projector's USB cable for LED control (Part 6). This removes the teal/pink bands completely.
  4. Check Adjust… → White balance is a number (about 4500 K), not automatic.
  5. If the picture went dark after the search, click Adjust… → Reset and run the search again with Red brightness at 100 %. Automatic exposure stays between 15.6 and 125 ms; shorter exposures only make the stripes worse.
  6. Turn on Stripe filter and try Frame averaging 2 or 4.
The picture is solid red, pink or white (overexposed)

Turn Auto on next to Red brightness, or lower the slider. In Adjust…, Reset returns the camera to its defaults.

"NO CAMERA", or the camera stays "CONNECTING"
  1. Close every other program that might use the camera (Camera, Zoom, Teams, OBS, the Arducam viewer).
  2. Unplug the camera, wait five seconds, plug it into a blue USB 3 port directly.
  3. Click Reconnect under the picture.
  4. Check Windows Settings → Privacy & security → Camera → Let desktop apps access your camera.
  5. Still failing: copy the camera diagnostics and send them with the log.
The laptop's own camera is shown instead of the Arducam

Settings → Camera: Refresh, choose the Arducam by name, Apply and reconnect camera, Save settings.

Only 1280 × 720 is available, at 10 fps

The camera is connected at USB 2 speed. Use a blue USB 3 port, the original cable and no hub; try flipping the USB-C plug at the camera.

Green blocks or bands, or flickering

Image data is being lost on the USB link: same fixes as above. Frames that are mostly solid green are skipped automatically.

The camera is slow at the highest resolution

At 5472 × 3648 the camera delivers 9 frames per second; that is the camera, not the app. For quick navigation choose 1920 × 1080 in the resolution list, then go back to the highest for focusing and snapshots.

Projector

The projector mirrors the laptop screen

Windows is in Duplicate mode. Press Win + P, choose Extend, then pick the projector under OUTPUT and click Open.

Nothing appears on the projector
  1. Check the Projector dot. Red means no output window: click Open on the Projector panel.
  2. Check the badge: OFF means black is projected. Click Red light · safe.
  3. With LED control, check the LEDs line; Test LEDs shows whether the board reacts.
  4. If the wrong display is covered, choose the projector under OUTPUT.
The pattern is the wrong size or in the wrong place

Check Settings → Projector → Image resolution (same as the projector display), Border 0 in step 1, and Alignment → Reset.

"Exposure not started"

The message says why: no pattern chosen; no exposure time; the stage did not stop moving within 20 seconds (it shows the controller's state; Alarm is explained under Stage); or the blue LED could not be switched on over USB (check the projector's USB cable, or turn LED control off).

The exposure stopped early

Esc, Stop exposure, STOP, or closing the app during an exposure stops it. The record marks it as stopped. If the status line says the exposure finished late, the window was busy; the light itself is switched off on time by a separate timer.

Stage

"Stage did not move"

See Part 5: ALARM, travel limits, or lost contact.

One axis does not move, the others do

Every command sent to the controller is written to HackerfabStepper.log, for example GRBL > G0 Y0.0100 ok. If the Y commands are there with ok, the controller accepted them and the problem is in the controller's settings or the wiring: check that axis's steps per mm ($101 for Y; a large step such as 100 µm shows it more clearly than 1 µm), its driver and its cable. If they are missing or show an error, send the log.

No ports appear in the setup window
  1. Check the controller is powered and its USB cable carries data (not charge-only).
  2. Click ↺ to rescan.
  3. Device Manager → Ports (COM & LPT): a warning icon means a driver is missing (CH340-based boards often need one).
The top bar says "Stage: simulation" although I picked a port

Opening the port failed; the reason is in the log (Stage connection failed (COM5): …). Usually another program has the port open (Arduino IDE serial monitor, a G-code sender). Close it and restart.

Arrow keys do nothing

The keyboard is in a text field. Click the camera picture and try again. Keys are also ignored during an exposure, autofocus, homing or tiling.

Autofocus stops with a message

It needs a live picture with detail and a start reasonably close to focus. Focus roughly by hand, show solid red or a pattern with sharp edges, and try again. No sharpest point within ±150 µm means focus is further away than that: get close by hand first. After any failure it returns the stage to the Z it started from.

An error box appears, or the app closes straight away
  1. Open HackerfabStepper.log and read the last lines.
  2. If it mentions the config file, rename config.toml to config.old.toml and start again with the defaults.

What the exe is

A PyInstaller one-file build of the stepper/ folder. It bundles Python 3.12, OpenCV (without its video-file codec), NumPy, Pillow, pyserial, toml, ttkbootstrap, pygrabber/comtypes (DirectShow camera modes and control ranges) and pyusb with libusb (projector LEDs). It leaves out ultralytics and PyTorch, and everything the app never loads (video codecs, SSL, unused image formats, test and packaging modules), which brings the exe down to about 50 MB. An experimental slim OpenCV build (packaging/build_opencv_slim.sh, build_exe.ps1 -SlimOpenCV, 29 MB exe) is not used until it has been confirmed on the stepper's camera.

Build

cd path\to\Hackerfab-Stepper\stepper
.\packaging\build_exe.ps1

It needs Python 3.10 to 3.13 (3.12 preferred), installs packaging\requirements-exe.txt into .venv-build, runs PyInstaller with packaging\HackerfabStepper.spec, runs the smoke test and leaves dist\HackerfabStepper.exe.

Smoke test

HackerfabStepper.exe --smoke-test builds the whole interface with no hardware, visits every page, checks that the USB library loads, starts a camera worker process against a camera that does not exist and checks that it reports back. It writes SMOKE TEST PASSED to the log and exits with code 0.

Tests

cd stepper
python -m unittest discover -s tests

156 tests: the camera worker with a simulated camera (mode choice, live controls, snapshots), image processing and the automatic camera settings against a simulated projector, LED control with a simulated USB device, the stepper logic (exposures, LED sequencing, STOP, safety timer, autofocus limits, stage position and homing, GRBL replies) and the main window with simulated camera, stage, displays and LEDs. GUI tests need a display and answer every dialog automatically.

  • Snapshots copied out of the snapshot folder
